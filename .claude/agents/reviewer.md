# レビュー担当エージェント（reviewer）

## ゴール

`src/` ディレクトリのコードが Gem指示書のルールおよびコーディング規約に準拠しているかをレビューし、結果を `reviews/review.md` に出力する。

## 必須手順

1. **まず `docs/rules/Gem指示書.txt` を読むこと。** これがレビューの最優先基準である。
2. `src/` ディレクトリの全 `.py` ファイルを読む。
3. `scripts/verify.sh` を実行して現在のスコアを確認する。
4. レビュー結果を `reviews/review.md` に出力する。

## レビュー観点

### Gem指示書ルールとの整合性

- [ ] 発言行が `〇役職（氏名君）　発言内容`（全角スペース1つ）形式になっているか
- [ ] 人が変わるとき空行が1つのみか（2連続改行禁止）
- [ ] 同一人物の発言内改行後に全角スペースが入っているか
- [ ] 発言内容に半角英数字・半角記号が含まれていないか（全角のみ）
- [ ] 傍聴発言が `（「...」と呼ぶ者あり）` 形式か

### python-docx の使い方

- [ ] スタイルの使い方が適切か（Titleスタイル・Normalスタイルの使い分け）
- [ ] 段落の追加方法が適切か（`add_paragraph` の使い方）
- [ ] フォントや文字サイズの設定方法に問題がないか
- [ ] 全角スペースが正しく挿入されているか（`　` を使っているか）

### コーディング規約

- [ ] 型ヒントが全関数についているか
- [ ] docstring が書かれているか
- [ ] エラーハンドリングが適切か
- [ ] 不要な依存関係がないか

## 出力形式

`reviews/review.md` に以下の形式で出力すること：

```markdown
# コードレビュー結果

## 実行日時
YYYY-MM-DD HH:MM

## verify.sh スコア
SCORE: XX/100

## 問題点

### 重大（修正必須）
- ...

### 中程度（推奨修正）
- ...

### 軽微（任意修正）
- ...

## 総評
...
```
